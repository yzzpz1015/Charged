## 1. 新增文件

### 1.1 `api/model/opencity_quant.py`
把官方 OpenCity-Plus 适配到本协议的 72→72、逐站 99 分位：

* 继承官方 `external/OpenCity/model/OpenCity/OpenCity.py::OpenCity`；官方末层 `Linear(24*skip_dim, 288)` 整层替换为分位头 `qhead`（LayerNorm → Linear(256) → GELU → Dropout(0.1) → Linear(72*99)）。
* `forward` 复刻官方时空上下文编码（时间 patch embedding、Laplacian PE、spatial embedding、encoder blocks、GCN），逐窗逐站 instance norm **只用历史 72h**，输出反归一化回 raw 空间，形状 `[B,N,72,Q]`。
* `build_graph`：距离 kNN（k=8）+ 自环 + 对称归一化，`A_mx = I + D^{-1/2} A D^{-1/2}`；`laplacian_pe` 复刻官方 `cal_lape`（含 eig 的符号约定），取 8 维。
* `load_pretrained`：剥离 `module.predictor.` 前缀、丢弃被替换的 `linear.*`，`strict=False` 加载；除 `qhead.*` 外缺键或任何多余键直接报错。实测加载 138 个张量。
* 时间编码沿用官方：`day=(hour+1)*60 ∈ [60,1440]`，ISO 星期 `Monday=1`。

### 1.2 `script/baselines/train_opencity.py`
* `--ft head`（默认，官方 eval 口径：冻结主干、只训 2.62M 头）与 `--ft full`（全参微调）。
* 损失：clean mask 加权的 raw 空间 pinball；早停看验证集 masked pinball。
* 默认超参：30 epoch、patience 5、AdamW lr 1e-3、wd 1e-4、hidden 256、dropout 0.1、99 分位、kNN 8、全训练集；batch windows 按站数自动（≤80: 8，≤300: 4，>300: 1）。
* `--eval_only` 只重评；支持 `BASELINE_TAG`（只改评测目录，ckpt 目录不变）。
* 产物：`ckpt/opencity/{city}/seed{s}.pth`、`metrics[_point]/opencity/{city}/H{24,48,72}_seed{s}.json`。

### 1.3 `script/baselines/summarize_point.py`
* 只读 `metrics_point/`，按 seed 聚合 mean±std，输出 H24/H48/H72 的 MAE/RMSE/R²。
* 额外计算 `nMAE = MAE / mean(y)`（五城可用城市简单平均），消除城市量纲差异。
* `n_test_windows` 少于该城全量时标 `*`；某城缺失时行尾标 `(n)`；UniTS 的整数 `horizon` 归一化为 `H{int}`；`_y_mean.json` 缓存各城 `mean(y)`。

## 2. 修改文件

### 2.1 `script/baselines/common.py`
全 baseline 共用的点预测评测（不重训即可重评）：

* `StreamingMetrics` 新增累计量 `pt_abs / pt_sse / pt_sy / pt_sy2 / pt_n`。
* 点预测口径：分位方法取 τ=0.5；非均匀分位网格（Chronos-Bolt 的 9 分位）用线性插值（`q_mid = interp(0.5, qs, idx)`）；样本方法（DeepAR/CSDI/TimeGrad/TSDiff/DiffSTG）取样本中位数。
* 每个 horizon 在 clean 站×窗上 pool：`mae`、`rmse`、`r2 = 1 − SSE/(Σy²−(Σy)²/n)`、`n_point_cells`，写入 JSON；日志同步打印 MAE/R²。
* 分位排序从 `_samples_from_quant` 移到 `_update_one` 统一执行（保留 `np.sort` 免费增益，避免排序两次）。
* `out_dirs`：`BASELINE_TAG=point` 时只把 metrics/diag 重定向到 `metrics_point/`、`diag_point/`，**ckpt 仍读原目录**，保证 `--eval_only` 可用且不覆盖旧概率结果。

### 2.2 `script/baselines/train_gluonts.py`
* 新增 `--predict_batch_size`：覆盖 predictor 推理 batch（只影响速度，不影响 TFT 结果）。
* 新增 `--slow_eval`：TFT 走官方 `predictor.predict`（逐条构造 `QuantileForecast`，慢），用于对账。
* 新增 `_fast_quant_chunk` / `_fast_sample_chunk`：直接调 `prediction_net`，按 `InferenceDataLoader` 组 batch，跳过 pydantic 逐条对象构造；TFT 输出按 `[B,Q,T]` 转置，DeepAR 输出 `[B,S,T]` 转成 `[T,S]`。
* 显式设置 `predictor.prediction_net.eval()`（否则 dropout 仍开启，快速路径与慢速路径数值不一致）；JHB 32 窗对账后 fast/slow 指标逐项一致。
* 修复设备：`create_predictor` 固定 `device="auto"`（会落到 cuda:0），训练/重评后显式设 `predictor.device` 并把 `prediction_net` 移到目标卡。
* 效果：TFT LOA 从约 42 min 降到约 4 min（`--predict_batch_size 4096`）。

### 2.3 `script/baselines/summarize.py`
* 新增 `--tag`：`--tag point` 读 `metrics_point/`，原 `metrics/` 的行为不变。

### 2.4 `script/baselines/train_unist.py`
* 新增真值张量 `yte` 与逐 horizon 点指标 `mae/rmse/r2/n_point_cells`。点预测取 UniTS 主干输出本身（残差池只加概率层，不改变点）。
* 新增 `BASELINE_TAG` 支持：指标目录切到 `metrics_point/`，ckpt 仍写 `ckpt/unist_pool/`。
* 保留 `[honest]`（不用滚动池）的 crpsΣ 参照输出。

### 2.5 `docs/baselines_protocol.md`
* §4 指标表新增 `mae / rmse / r2 / n_point_cells`，并写明点预测定义、`nMAE`、`BASELINE_TAG=point` 不重训重评。
* §6 方法表新增 #20 `UniTS-FT + pool`（公开 x64 权重、MEL/SPO 附录行）与 #21 `OpenCity-Plus`（公开权重、官方 head-only 口径、2.62M/25.06M 可训）。

## 4. 期间修复的问题

1. **TFT 评测过慢**：官方 `predictor.predict` 每条 entry 构造 99 个 `Quantile` 对象（pydantic 开销约 5 ms/entry）。改走 `prediction_net` 后 LOA ~4 min；但快速路径初始与慢速路径差 0.0003，根因是未调用 `.eval()`（dropout 未关），修复后逐项一致。
2. **设备抢占**：`TemporalFusionTransformerEstimator.create_predictor` 硬编码 `device="auto"`，所有 TFT 重评会挤到 cuda:0；显式 pin `predictor.device` 并移动网络后解决。
3. **Moirai OOM**：Mixture 分布把 `[batch, num_samples, components, 72]` 全展开；`batch_windows=32 + batch_series=4096` 在 LOA/MEL/SPO 均 OOM。改为 8/512 后五城跑通。
4. **DeepAR / ISQF SZH OOM**：8 窗 × 843 站 × 200 样本 + `predict_batch_size=4096` 需 7.4 GiB 以上；SZH 改为 256 窗子集 + batch 512。ISQF LOA 也在 4096 下 OOM（ISQF 输出比 StudentT 更占显存），改 512。
5. **DiffSTG OOM**：SZH 全 station 联合 GRU/扩散，默认采样块过大（18.6 GiB 申请失败）；LOA 亦有采样 OOM。改为 `--sample_windows 8 --sample_chunk 8`（SZH 用 2/8）后运行。
6. **CSDI MEL 同卡 OOM**：与 TSDiff MEL 共用 GPU2 时显存不足；改到空闲 GPU1 重跑。
7. **串行链改为按城并行**：原先每个方法用 `for city in ...` 串行跑五城。停掉四个父 shell（只 kill 精确 PID，子进程继续跑当前城），之后按空闲 GPU 逐城并行，避免串行 ETA 叠加。未做任何设备级 kill。
8. **UniTS 点指标与 tag**：原先只输出概率指标且目录不可切换；补 `yte`、点指标与 `BASELINE_TAG`，五城统一口径。

## 5. 产物与口径

* 点预测 JSON：`result/baselines/metrics_point/{method}/{city}/H{24,48,72}_seed{s}.json`。
* ckpt 目录不变：`result/baselines/ckpt/{method}/{city}/seed{s}.pth`；**没有覆盖任何旧概率结果**。
* 点预测定义：分位方法 τ=0.5（非均匀网格线性插值），样本方法样本中位数；只在 clean 站×窗上计算，pool 后给 MAE/RMSE/R²。
* `nMAE = MAE / mean(y)`，五城简单平均；SZH 的 R² 被站间水平差主导，读表以 MAE/nMAE 为主。
* `*`：该城测试窗为子集。当前：CSDI 四城 256 窗、SZH 128 窗；TSDiff/DiffSTG 的 SZH 为 256 窗；DeepAR/ISQF 的 SZH 为 256 窗。
* 扩散/零样本只评 seed 0（与其概率主表一致）；主干类 3 seeds；UniTS 单 seed、附录行。

## 7. 复现命令

```bash
# OpenCity：seed0 训练+评测（概率目录）
python3 script/baselines/train_opencity.py --city LOA --seed 0 --device 0

# OpenCity：seed1/2 训练+点预测评测（ckpt 仍写原目录）

BASELINE_TAG=point python3 script/baselines/train_quant_backbone.py --method itransformer --city LOA --seed 0 --device 0 --eval_only
BASELINE_TAG=point python3 script/baselines/train_gluonts.py --method tft --city LOA --seed 0 --device 0 --eval_only --predict_batch_size 4096 --no_diag

# 汇总点预测

python3 script/baselines/summarize_point.py --seeds 0,1,2 --metric rmse
python3 script/baselines/summarize_point.py --seeds 0,1,2 --metric r2

python3 script/baselines/summarize.py --tag point
```
